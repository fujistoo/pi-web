pi-web feature team

One lead per feature, spawned on demand, delegating to members it spawns itself. Members message each other directly; every escalation that reaches you is a blocking decision.

Feature run lifecycle

A run moves from delegation through recovery, and ends only when you confirm completion — decommissioning removes the runtime and keeps the record.

Lead boundaries

One lead per feature, spawned when you start the run. The lead holds the run record, decomposes the work, spawns its members, verifies what they produce, and filters what reaches you. On completion the runtime is removed; the feature record stays.

Build work — five gaps

  • Nested delegation, opt-in per profile, with a depth cap
  • Per-feature roster, not the fixed six roles
  • Escalation tool with the three reasons, plus pending-request UI
  • Close-run action and worktree cleanup
  • Team panel over .product/features/
